# Подключение облака и аккаунтов

Приложение использует Supabase для регистрации по email, облачной базы данных и приватного хранения изображений.

## 1. Создай проект Supabase

Создай новый проект в Supabase Dashboard и сохрани его пароль базы данных в надёжном месте.

## 2. Создай таблицу и хранилище

Открой SQL Editor в панели проекта, вставь содержимое файла `schema.sql` и выполни запрос. Он создаст таблицу `planner_data`, закрытый bucket для изображений и политики доступа. Каждая учетная запись сможет читать и менять только свои данные и файлы.

## 3. Настрой адреса для писем

В Authentication → URL Configuration укажи базовый адрес приложения в Site URL **без `/**`**. Шаблоны разрешены только в списке Redirect URLs. Для этой локальной разработки поставь Site URL:

- `http://127.0.0.1:5173`

В Redirect URLs добавь оба адреса, чтобы вход работал независимо от того, какое имя хоста ты откроешь:

- `http://127.0.0.1:5173/**`
- `http://localhost:5173/**`

Email-подтверждение можно оставить включённым. После регистрации приложение покажет сообщение проверить почту.

## 4. Добавь ключи в приложение

Скопируй `.env.example` в `.env.local` в корне проекта и заполни:

- `VITE_SUPABASE_URL` — Project URL из панели Supabase;
- `VITE_SUPABASE_PUBLISHABLE_KEY` — publishable key проекта.

Затем перезапусти dev-сервер. Publishable key предназначен для браузерного клиента; `service_role` или secret key в приложение добавлять нельзя.

## 5. Зарегистрируйся и перенеси данные

Открой приложение и выбери «Регистрация». При первом входе, если для аккаунта ещё нет облачных данных, приложение перенесёт сезоны и работы из `localStorage`, а изображения — из IndexedDB в закрытое хранилище Supabase. Исходная локальная копия при переносе не удаляется.

Если аккаунт уже содержит данные, они загрузятся из облака вместо текущего локального набора. Перед первым входом лучше сохранить резервную копию браузерных данных, если там есть важные изменения.
